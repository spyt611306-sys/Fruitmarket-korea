# 푸릇마켓 Part 46 플랫폼 기능 벤치마크 및 반영표

## 검토 기준

국내 대형 커머스 플랫폼의 공개 판매자센터·도움말·정산 안내에서 공통적으로 확인되는 기능을 기준으로 검토했다. 특정 플랫폼의 비공개 운영 로직을 복제하지 않고, 오픈마켓 운영에 필요한 공통 통제만 푸릇마켓 구조에 맞게 반영했다.

검토한 공개 범위는 다음과 같다.

- 쿠팡 Wing: 상품 등록, 옵션·이미지·상품정보제공고시, 주문·재고·문의·정산·통계
- 네이버 스마트스토어: 상품·SKU·재고, 발주·발송, 구매확정·정산, 문의·리뷰·마케팅
- 컬리 공개 화면: 판매자 표시, 상품 원산지·보관·중량·배송 정보, 품질기준, 결제수단

## Part 46에서 추가한 핵심 차이

1. 상품이 `ON_SALE` 또는 `APPROVED`로 바뀔 때 DB 트리거가 판매자 검증, 판매자 계약, 중개 고지 승인, 상품정보제공, 반품정책, 금지표현 검토, 과일 신선정보 승인을 함께 검사한다.
2. 관리자 화면의 버튼만 숨기는 방식이 아니라 데이터베이스가 판매승인 우회를 거부한다.
3. 판매자 정산은 총매출만 표시하지 않고 환불, 조정, 위험유보, 지급대행 대사 기록을 분리한다.
4. 플랫폼 분쟁사건을 주문 클레임과 별도 관리하고 최초 안내 및 처리방안 기한을 영업일로 계산한다.
5. 신선식품은 일반 SKU 재고에 더해 수확·포장·권장섭취일이 있는 로트로 관리하고 FEFO로 배정한다.

## 아직 외부 계정에서 검증해야 하는 항목

- 실제 Supabase 프로젝트 SQL 실행과 마이그레이션 롤백
- Toss 테스트·라이브 승인, 부분취소, 웹훅 재전송
- 정산 지급대행 계약사의 실제 API 응답과 실패 복구
- 카카오 OAuth, 이메일 발송, PASS·사업자 진위확인 공급자
- 택배사 운송장 API 및 배송상태 대사
- 법률전문가가 승인한 약관·고지·분쟁기준

이 문서는 기능 비교표이며 라이브 운영 승인서가 아니다.
