# Part 46 프로세스 시뮬레이션 결과

로컬 정적검사와 상태기계 시뮬레이션에서 다음 흐름을 검증했다.

## 상품

- DRAFT → REVIEW_REQUESTED → APPROVED → ON_SALE 정상 전이
- DRAFT → ON_SALE 승인우회 차단
- 판매자 미검증, 계약 미동의, 법정정보 미완료, 신선정보 미승인, 리콜 로트가 있으면 판매 차단

## 재고·주문

- 권장섭취일이 빠른 로트를 우선 배정
- FAILED, BLOCKED, RECALLING 로트 제외
- 안전재고 부족 시 주문 차단
- 동일 멱등키 주문 준비 재호출 시 새 주문 미생성
- 결제 승인 재호출 시 재고 중복차감 방지
- 결제 금액 불일치 차단
- 판매자별 주문상품 그룹 분리

## 배송·클레임·정산

- READY → PREPARING → SHIPPED → IN_TRANSIT → DELIVERED 전이
- 환불금액을 정산에서 차감
- 총매출 - 수수료 - 환불 + 조정 - 유보 = 지급예정액 산식
- 3영업일·10영업일 기한의 주말 제외 계산
- 리콜 대상 구매자 중복제거 통지

## 버튼·UI

- 처리 중 버튼 재클릭 차단
- 390px·1365px에서 Part 46 패널 5개 단일 생성
- 중복 ID 0개
- 문서 가로 넘침 0px
- 메인 배너 3장 3초 자동전환
- 과일 아이콘 22개 표시

## 검증 한계

실제 Supabase·PG·택배·지급대행 계정에 연결한 종단간 테스트가 아니다. 실서비스 전 별도 스테이징에서 실제 결제·환불·부분취소·웹훅·정산·리콜 모의훈련이 필요하다.
