# 푸릇마켓 Part 48 관리자 상호보호 운영 가이드

## 공통 처리원칙

1. 신고·위험점수만으로 환불거절, 정산몰수, 영구정지를 확정하지 않습니다.
2. 피해 확산 우려가 크면 종료시각이 있는 최소범위의 임시조치만 적용합니다.
3. 주문 당시 상품·판매자·가격·배송·반품조건 스냅샷을 먼저 보존합니다.
4. 구매자·판매자·택배사·PG 자료를 출처별로 분리해 수집합니다.
5. 증거 원본은 해시와 함께 저장하고 수정·삭제하지 않습니다.
6. 결정사유, 적용조치, 금액, 승인자, 통지시각과 이의제기 기한을 기록합니다.
7. 최종 정지·해지는 서로 다른 관리자 2명의 승인이 모여야 확정됩니다.
8. 이의제기는 가능하면 최초 결정자와 다른 담당자가 재검토합니다.

## 판매자 부정행위 사건

- 허위송장: 택배사 집하 스캔, 송장 재사용, 출고기한, 포장기록 확인
- 반복 미출고: 판매자 귀책 취소율, 재고·출고 이력, 소비자 보상액 확인
- 품질·원산지 허위: 상품 스냅샷, 로트·수확·검사·원산지 증빙 확인
- 리콜·위해상품: 해당 상품과 로트를 즉시 임시 중지하고 구매자 통지대상 추출
- 계정탈취: 로그인·MFA·정산계좌 변경 이력 확인
- 정산계좌 변경: 72시간 지급 냉각, MFA, 예금주·사업자 재검증

## 소비자 부정행위 사건

- 중복환불: 주문·클레임·PG 환불·차지백 원장을 대조해 중복분만 차단
- 빈 상자·바꿔치기: 회수 중량, 포장상태, 상품 식별, 개봉·검수사진 확인
- 허위 미수령: 배송완료 스캔만으로 확정하지 않고 수령증거·오배송 가능성 확인
- 다계정 쿠폰: 동일 주소 단독으로 확정하지 않고 결제수단 해시·주문행동·계정관계를 함께 검토
- 정상 하자: 리콜·배송지연·사진·판매자 인정이 있으면 위험점수와 별도로 신속 처리

## 허위신고 통제

- 신고자가 실제 주문의 구매자 또는 판매자인지 확인합니다.
- 하루 5건 제한을 넘긴 반복 신고는 접수하지 않습니다.
- 기각된 신고가 반복되면 허위신고 위험신호로 별도 심사합니다.
- 신고했다는 이유만으로 상대방 또는 신고자에게 보복하지 않습니다.

## 최종 불이익 승인

- 첫 번째 관리자가 `SUSPEND` 또는 `TERMINATE`와 구체적 사유를 기록합니다.
- 시스템은 사건을 `DECISION_PENDING`으로 유지하고 두 번째 승인을 요구합니다.
- 7일 이내 다른 관리자 한 명이 동일 결정을 승인해야 최종 반영됩니다.
- 두 관리자의 결정이 다르면 사건을 재조사하고 자동 확정하지 않습니다.

## 법적으로 위험한 운영

- 증거 없이 판매자 정산에서 임의 차감
- 소비자에게 현실적으로 제출하기 어려운 자료를 일률 요구
- 동일 주소·기기만으로 연관계정 확정
- 위험점수만으로 영구정지·최종 환불거절
- 분쟁 중 증거 수정·삭제
- 약관으로 플랫폼의 고의·중대한 과실 책임까지 포괄 면제

## 설치·운영 확인

`19_mutual_fraud_and_abuse_protection.sql` 후 `20_part48_verification.sql`을 실행합니다. `part48_mutual_protection_readiness.release_ready`는 담당인력, 증거절차, 정산계좌 냉각, 배송증거 연동, 오탐 검토, 이의제기 절차가 실제 운영에서 모두 `VERIFIED`가 된 뒤에만 `true`여야 합니다.
