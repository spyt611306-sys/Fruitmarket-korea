# 푸릇마켓 법적·운영 보호장치

## 중요한 한계

코드나 약관만으로 관리자의 법적 책임을 완전히 없앨 수 없다. 실제 거래구조, 광고표현, 판매자 관리, 사고 대응과 기록이 코드와 일치해야 한다. 부당하게 소비자 권리를 제한하거나 모든 책임을 판매자에게 전가하는 문구는 오히려 무효 또는 분쟁 위험이 될 수 있다. 라이브 전환 전 전자상거래·개인정보·식품표시 분야 전문가의 검토가 필요하다.

## 1. 통신판매중개 운영

- 푸릇마켓이 중개자라는 사실과 실제 판매자를 상품 상세, 주문서, 푸터에 표시한다.
- 판매자 상호, 대표자, 사업자번호, 통신판매업 신고정보, 주소, 고객센터를 확인하고 주문 시점 스냅샷으로 보존한다.
- 판매자 정보가 미검증이거나 계약에 동의하지 않으면 상품 판매승인을 차단한다.
- 플랫폼이 분쟁 접수, 사실확인, 판매자 답변 요청, 처리결과 통지를 기록한다.
- 단순히 “플랫폼은 책임이 없다”는 포괄 문구를 사용하지 않는다.

## 2. 상품정보·광고표현

- 원산지, 품명·품종, 중량·수량, 생산자, 보관방법, 배송·반품 기준을 상품별로 저장한다.
- 당도·등급·무농약·유기·GAP·잔류농약 검사 등의 표현은 증빙 유형, 발급기관, 유효기간, 검증상태와 연결한다.
- 질병 예방·치료, 객관적 근거 없는 최상급·비교우위, 미확인 인증 표현을 금지한다.
- 상품 중요정보 변경 시 승인상태를 되돌리고 재심사를 요구한다.

## 3. 청약철회·환불

- 신선식품이라는 이유만으로 모든 취소·환불을 일괄 거부하지 않는다.
- 단순 변심 제한은 상품 특성, 훼손 가능성, 사전 고지 등 실제 요건을 확인한다.
- 오배송, 하자, 부패, 파손, 표시와 다른 품질은 증빙과 출고 로트를 확인해 교환·환불 심사한다.
- 환불은 PG 서버 API 성공 후에만 DB를 완료 상태로 변경한다.
- 부분환불은 주문상품·수량별 원장을 남기고 정산에서 차감한다.

## 4. 결제·자금·정산

- 브라우저가 보낸 가격, 할인, 배송비, 포인트를 신뢰하지 않고 서버가 재계산한다.
- `paymentKey`, `orderId`, `amount`를 서버에서 대조한다.
- 승인·취소·웹훅은 멱등키와 고유 제약으로 중복처리를 막는다.
- 플랫폼이 판매대금을 임의 보관·송금하는 구조를 사용하지 않고 계약된 PG·지급대행을 사용한다.
- 정산은 구매확정, 환불, 수수료, 조정, 위험유보, 지급결과 대사를 분리한다.
- 정산 완료는 실제 지급대행 완료가 확인된 뒤에만 허용한다.

## 5. 분쟁처리

- 주문 클레임과 플랫폼 분쟁조정 사건을 분리한다.
- 접수, 담당자, 판매자 답변, 구매자 보완, 중재, 결과, 보상금액과 증빙을 이벤트 원장으로 보존한다.
- 최초 진행안내와 처리방안 기한을 영업일로 계산한다.
- 기한초과 사건은 자동으로 HIGH 또는 CRITICAL로 올리고 관리자 알림 대상으로 만든다.
- 개인정보, 결제, 식품안전 사건은 일반 문의보다 높은 우선순위로 운영한다.

## 6. 개인정보

- 브라우저에는 Supabase publishable key만 사용한다.
- service-role, DB 비밀번호, Toss secret은 Edge Function Secret에만 저장한다.
- RLS, 관리자 MFA, 역할변경 차단, 접속·감사로그, 암호화, 보관기간과 파기작업을 적용한다.
- 정산계좌는 암호화된 값과 마지막 네 자리만 분리해 저장한다.
- 법적 보존 또는 분쟁 중인 기록은 `legal_holds`로 파기에서 제외한다.
- 보존기간 종료 후 마스킹·삭제 작업 결과를 기록한다.

## 7. 기록 보존

Part 46 기본 정책은 다음 기록군을 분리한다.

- 광고 표시: 6개월
- 계약·청약철회: 5년
- 대금결제·재화공급: 5년
- 소비자 불만·분쟁: 3년
- 접속기록: 내부 보안정책에 따른 기간

법령·업종·분쟁 상황에 따라 더 길게 보존해야 할 수 있으므로 실제 정책 승인이 필요하다.

## 8. 관리자 보호를 위한 운영 원칙

- 승인, 반려, 판매중지, 환불, 제재, 정산유보, 개인정보 열람·파기는 사유와 증빙을 필수로 남긴다.
- 고액 환불·정산은 이중승인을 사용한다.
- 법적 고지와 판매자 계약은 버전·해시·승인자·시행일을 저장한다.
- 사고 시 상품·로트·판매자를 즉시 차단하되 구매자 통지와 회수상태를 함께 관리한다.
- 운영 준비 게이트가 하나라도 미검증이면 결제·정산 라이브 설정을 활성화하지 않는다.

## 라이브 전환 전 외부 검토 체크

- 통신판매중개 구조와 사업자·통신판매업 신고 내용 일치
- 구매안전서비스·PG·지급대행 계약
- 이용약관, 개인정보처리방침, 판매자약관, 분쟁처리기준
- 상품정보제공고시와 농산물 원산지 표시
- 식품·건강 관련 광고표현 검수
- 개인정보 내부관리계획과 유출대응 절차
- 세금계산서·정산명세서·원천징수 등 세무 처리
